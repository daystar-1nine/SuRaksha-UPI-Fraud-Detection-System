# QR Code Signing & Registry 🔑

Physical QR sticker swapping is a growing threat in retail environments. Scammers paste malicious QR printouts over merchant boards to divert customer payments to their own accounts. SuRaksha uses cryptographic signing to verify that QR codes are genuine.

---

## 🔒 Cryptographic Signing Flow

SuRaksha enforces a secure verification loop. The signature is computed using a secret key registered with our database, verifying that the QR was generated by an authorized merchant:

```
    [ MERCHANT GATEWAY ]                      [ CUSTOMER DEVICE ]
  Generates UPI QR parameters               Scans QR Code & gets VPA,
  (VPA, Payee Name) & signs                  Name, and Signature
  using WebCrypto API.                                │
           │                                          │
           ▼                                          ▼
┌──────────────────────┐                     ┌──────────────────┐
│  upi://pay?...       │                     │ Query /analyze/qr│
│  &sign=SHA256(...)   ├────────────────────►│ Backend API      │
└──────────────────────┘                     └────────┬─────────┘
                                                      │
                                                      ▼
                                            [ BACKEND REGISTRY ]
                                            Validates signature using
                                            the VPA's secret key.
                                                      │
                         ┌────────────────────────────┴────────────────────────────┐
                         ▼ (Match)                                                 ▼ (Mismatch / Missing)
             ┌──────────────────────┐                                  ┌──────────────────────┐
             │ verified_merchant    │                                  │ sticker_tamper       │
             │ Risk: 0% (SAFE)      │                                  │ Risk: 98% (BLOCK)    │
             └──────────────────────┘                                  └──────────────────────┘
```

## 🔑 Signature Computation

To prevent credential leaks, the signature validation is performed **entirely on the backend**. 

### 1. Verification Registry
The backend defines a private dictionary mapping authorized merchant VPAs to names and secret verification keys:
```python
# In backend/utils/constants.py
TRUSTED_MERCHANTS = {
    "sharmakirana@upi": {"name": "Sharma Kirana Store", "secret": "SuRakshaShield2026"},
    "starcafe@upi": {"name": "Star Cafe", "secret": "SuRakshaShield2026"},
    "arogyamedical@upi": {"name": "Arogya Pharmacy", "secret": "SuRakshaShield2026"}
}
```

### 2. Signature Validation Math
When the user scans a QR, the parameters `pa` (payee VPA address), `pn` (payee display name), and `sign` (signature) are extracted. If the VPA exists in the trusted merchants registry, the server computes the expected signature:
$$\text{Expected Signature} = \text{SHA-256}(\text{pn.toLowerCase()} + \text{pa.toLowerCase()} + \text{SecretKey})$$

If the computed signature matches the query's `sign` parameter, the merchant is verified.

## ⚙️ Threat Mitigation Rules

During a QR analysis, the pipeline applies strict risk overrides based on signature results:

| Signature Status | Risk Rating | Threat Signal Raised | System Action |
| :--- | :--- | :--- | :--- |
| **No Signature** (for a registered merchant VPA) | **95% (CRITICAL)** | `Physical Sticker Swap` | Displays red warning banner; prompts user to confirm merchant identity. |
| **Signature Mismatch** | **98% (CRITICAL)** | `Spoofed QR Board Hack` | Forces immediate block; alert warns the user of QR spoofing. |
| **Signature Match** | **0% (SAFE)** | `Verified Merchant Shield` | Renders a glowing green certificate shield showing verified store details. |

## 🚫 Phishing Redirect Defense

Many UPI scams use QR codes to redirect customers to phishing websites mimicking bank portals or reward centers rather than initiating direct payments.

To prevent these redirect attacks, the QR analyzer enforces protocol validation:
- **Rule**: If the QR payload does not start with the standard UPI URI scheme (`upi://`), it is flagged immediately.
- **Action**: The system registers a `malicious_web_redirect` threat signal with a score of `10.0`, overriding the transaction score to **100% (CRITICAL)** and forcing an immediate block.
- **Example**: Scans containing `https://gpay-rewards.center.in/claim` are blocked instantly before the browser attempts to resolve the URL.
